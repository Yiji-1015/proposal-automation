## 1. 회의 핵심 요약

이번 회의의 핵심은 남동발전 사례를 기반으로, 기획팀의 제안 업무를 AI로 보조하는 자동화 체계를 설계하는 것이다. 목표는 제안서를 완전 자동 작성하는 것이 아니라, 사업 검토부터 RFP 분석, R&R 배정, 제안서 초안 생성까지의 반복 작업을 줄이고 사람이 더 중요한 판단과 고도화에 집중할 수 있게 만드는 것이다.

현재 가장 큰 문제는 제안 업무에 필요한 자료가 드라이브에 흩어져 있고, 사람이 보기 위한 문서와 AI가 이해하기 쉬운 자료가 구분되어 있지 않다는 점이다. 따라서 기존 제안서, 회사 소개, 솔루션 정보, 실적, 레퍼런스, 템플릿 등을 AI가 활용 가능한 형태로 재정리해야 한다.

회의에서는 우선 전체 파이프라인과 방법론을 설계한 뒤, 설계에 맞춰 필요한 데이터를 모으고, AI 구현 및 반복 개선을 진행하기로 했다. 목표 일정은 6월 말까지 설계, 7월 중 데이터 정리와 AI 구현, 7월 말까지 1차 개선 완료다.

## 2. 만들고자 하는 전체 프로세스

회의에서 정의된 제안 자동화 흐름은 다음 4단계다.

1. 사업성 분석
   - 해당 사업에 참여할지 여부를 판단하는 단계
   - 사업을 어떤 기준으로 평가할지 방법론 수립 필요
   - AI가 초안을 빠르게 뽑고, 사람이 빠르게 판단하는 구조가 목표

2. RFP 분석
   - 제안서를 쓰기로 결정한 뒤, 어떻게 쓸지 판단하는 단계
   - RFP 요건, 평가 기준, 주요 요구사항, 제안 전략을 분석
   - 매번 문건 검토에 오래 걸리는 과정을 자동화하고자 함

3. 사업 참여 의사결정 및 R&R 배정
   - 제안 참여가 결정되면 누가 어떤 역할을 맡을지 정리
   - 데이터/AI, 인프라 설계, 제안서 작성 등 역할에는 반복 패턴이 있음
   - 회사와 팀 내부 역할을 카테고리화해 자동으로 R&R 협의 자료를 만들 필요가 있음

4. 제안서 초안 생성
   - RFP 요건과 R&R을 기반으로 제안서의 기본 목차와 장표 뼈대를 생성
   - 장표별 제목, 소제목, 거버닝 메시지, 기본 구성까지는 AI가 생성하는 것이 목표
   - 최종 디자인과 상세 내용 고도화는 사람이 수행

## 3. 현재 문제 인식

### 3.1 자료는 있으나 AI용으로 정리되어 있지 않음

기존 제안서, 회사 소개, 솔루션 정보, 레퍼런스 자료는 이미 상당히 축적되어 있다. 다만 현재 자료는 사람이 열람하고 복사/붙여넣기 하는 용도에 가깝고, AI가 안정적으로 이해하고 재사용하기에는 구조화가 부족하다.

필요한 전환 방향은 다음과 같다.

- 쓸모 있는 자료만 선별
- 문서 유형별로 분류
- AI가 읽기 쉬운 Markdown, HTML, 텍스트 형태로 가공
- 기본 템플릿과 작성 가이드 분리
- 주기적으로 업데이트 가능한 기준 자료 체계 마련

### 3.2 매번 제안서를 처음부터 시작하는 비용이 큼

제안 기간이 점점 짧아지고 있어, 제안서 작성 때마다 목차, 메시지, 장표 구조, 기본 문구를 처음부터 만드는 방식은 부담이 크다. 완전 자동화를 목표로 하기보다는, 사람이 판단해야 하는 영역과 AI가 초안을 만들 수 있는 영역을 분리해야 한다.

회의에서 합의된 현실적인 목표는 다음과 같다.

- 사업성과 RFP 분석은 AI가 초안을 생성
- 사람은 초안을 보고 빠르게 의사결정
- 제안서 장표는 최소한 기본 뼈대까지 자동 생성
- 사람은 구성도, 캡처 이미지, 디자인 완성도, 핵심 전략을 보완

### 3.3 기획팀 특화 에이전트가 필요함

이 체계는 전사 공용 AI가 아니라 기획팀의 제안 업무에 특화된 에이전트 또는 작업 환경으로 보는 것이 적절하다. 따라서 일반적인 검색/요약 수준이 아니라, 기획팀이 실제로 사용하는 제안 방식과 산출물 형식에 맞춰야 한다.

## 4. 필요한 산출물

회의에서 언급된 주요 산출물은 다음과 같다.

### 4.1 제안 업무 방법론

- 사업성 분석 기준
- RFP 분석 기준
- 제안 참여 의사결정 기준
- R&R 배정 기준
- 제안서 목차 및 장표 구성 기준

### 4.2 AI용 지식 베이스

AI가 참고할 수 있는 고정 자료 묶음이 필요하다.

- 회사 정보
- 솔루션 모듈
- 주요 실적
- 지원 사업 레퍼런스
- 파트너 및 제품 정보
- 제안서에 반복적으로 들어가는 기본 설명

형태는 Google Drive 전체 연동보다, 선별된 폴더 또는 파일 묶음이 적절하다는 의견이 있었다. 너무 많은 자료를 넣으면 비용과 품질 관리가 어려워진다.

### 4.3 AI용 제안서 템플릿

기존 사람이 쓰는 PPT 템플릿과 별개로, AI가 이해하고 활용하기 위한 템플릿이 필요하다.

예상 구성은 다음과 같다.

- 기본 목차
- 장표별 작성 가이드
- 장표별 제목/소제목/거버닝 메시지 규칙
- 필요한 기본 디자인 패턴
- 샘플 장표
- 출력 형식 기준

회의에서는 기본 자료 HTML 파일, 기본 템플릿 PPT 파일, 작성 가이드 파일 정도만 있어도 1차 공정화가 가능할 수 있다는 의견이 나왔다.

### 4.4 제안서 생성 파이프라인

예상 파이프라인은 다음과 같다.

1. RFP 또는 사업 문건 입력
2. 사업성 분석 생성
3. RFP 분석 및 요건 정리
4. 제안 전략 및 스토리보드 생성
5. 장표별 구성안 생성
6. PPT 템플릿 기반 초안 생성
7. 사람이 디자인과 내용 고도화
8. 결과 품질을 보고 지식 베이스와 프롬프트 개선

## 5. 기술적 논의

### 5.1 자료 형식

PPT 파일을 그대로 많이 넣는 방식보다는, 핵심 내용은 Markdown, 텍스트, HTML 형태로 정리하는 것이 더 적절하다는 의견이 있었다. 다만 디자인과 장표 패턴을 전달하기 위해서는 샘플 PPT 또는 템플릿 PPT가 필요하다.

검토된 형식은 다음과 같다.

- Markdown 또는 텍스트: 내용 지식 정리용
- HTML: 구조화된 장표 구성안 또는 AI가 읽기 쉬운 문서용
- PPT 템플릿: 실제 장표 디자인과 레이아웃 기준용
- 장표 단위 이미지/PPT 분리: 필요한 장표를 재사용하기 위한 방식

### 5.2 Vector DB 필요성

Vector DB 도입도 언급되었지만, 초기에는 Markdown이나 텍스트 파일만으로 충분할 수 있다는 의견이 있었다. PPT 내용이 서로 비슷한 경우가 많아 의미 검색만으로는 원하는 자료를 정확히 가져오기 어려울 수 있으므로, 폴더 구조와 레퍼런스 매핑을 잘 설계하는 것이 중요하다.

### 5.3 비용 관리

API 사용료가 과도하게 나오지 않도록 주의해야 한다는 논의가 있었다. 초기에 소액으로 사용량을 확인하고, 필요 금액이 명확해지면 예산 품의를 올리는 방식이 적절하다.

언급된 방향은 다음과 같다.

- 초기 API 비용은 월 2만 원 수준으로 테스트
- 필요 시 5만 원 또는 10만 원 등으로 예산 산정
- 고비용 모델에 의존하지 않고 Claude Sonnet 수준에서 가능한지 검증
- 팀 공용 계정 또는 API 기반 작업 환경 중 비용 효율적인 방식 검토

### 5.4 작업 환경

팀 공용 계정 또는 사내 전용 UI를 만드는 방안이 언급되었다. 사용자는 파일을 업로드하고, 정해진 경로의 자료를 기반으로 결과물을 생성하는 간단한 작업 환경을 쓰는 구조가 될 수 있다.

가능한 방향은 다음과 같다.

- 별도 회사 계정 생성
- Claude Code 또는 유사 도구 연동
- 파일 업로드 기반 UI 제공
- 내부망 또는 VPN 기반 사용
- 제안 담당자가 바뀌어도 동일한 공용 작업 환경 사용

## 6. 참고 사례

회의 중 중소벤처기업진흥원 제안서 기술 파트 작성 사례가 공유되었다.

작업 흐름은 다음과 같았다.

1. 사업성 분석 문서 생성
2. 제안 전략과 장표 구성 방안을 HTML로 작성
3. HTML을 수기로 편집해 장표별 내용 확정
4. PPT 템플릿에 소제목, 거버닝 메시지, 요구사항, 코드/표 구조 등을 세팅
5. 샘플 장표 2개를 뒤에 넣어 디자인 패턴을 학습하도록 함
6. AI가 템플릿을 기반으로 장표 초안을 생성
7. 구성도와 캡처 이미지는 사람이 추가 편집

이 방식으로 완전 자동화는 아니지만, 제안서의 상당 부분을 초안 수준까지 자동화할 가능성을 확인했다.

## 9. 정리된 방향성

이번 프로젝트의 방향은 "AI가 제안서를 대신 완성한다"가 아니라 "AI가 반복적인 초안 작업을 맡고, 사람은 판단과 고도화에 집중한다"에 가깝다.

따라서 우선순위는 다음 순서가 적절하다.

1. 사람이 하는 제안 업무 흐름을 명확히 정의
2. AI가 읽을 수 있는 자료와 템플릿을 최소 단위로 구성
3. 사업성 분석, RFP 분석, 장표 초안 생성을 하나의 파이프라인으로 연결
4. 실제 제안 사례로 반복 테스트
5. 비용과 품질을 보며 도구와 구현 방식을 조정

초기에는 완성도보다 재현 가능한 프로세스를 만드는 것이 중요하다. 이후 제안 사례가 누적되면 지식 베이스와 템플릿을 점진적으로 고도화할 수 있다.
